# Hidden-Rule Manifest for the Fast Bench, Campaign 1

**Companion to:** Generative Closure — Cellular Automaton Drosophila, Spec v0.2.2
**Manifest version:** campaign-1.0
**Status:** Ready to lock for first throughput campaign.

---

## What this document is

Spec v0.2.2 §1.1 requires the first campaign to use a stratified pool of 15
hidden rules — five library-aligned, five adversarial, five random — and
requires the exact rule identities to be fixed in a versioned manifest before
the first throughput run. §14.3 leaves the manifest membership open. This
document closes that question and explains how the choices were verified.

The deliverables in this directory are:

- `campaign1_manifest.json` — the canonical manifest, machine-readable.
- `build_manifest.py` — the analysis library: indexing, primitive
  construction, alignment computation. Also runs as a script that prints
  raw alignment tables for sanity checking. It does **not** emit the frozen
  canonical manifest artifact.
- `search_adversarial.py` — the adversarial-rule search procedure. It writes
  an intermediate `adversarial_selection.json` for the assembler.
- `assemble_manifest.py` — the sole canonical manifest emitter. It reads the
  adversarial selection, scores everything, and writes the frozen
  `campaign1_manifest.json`.
- `MANIFEST_MEMO.md` — this document.

Every number in the manifest is reproducible from these files. There are no
hand-tuned magic constants beyond the random seeds, which are recorded.

---

## Why the manifest matters

Success criterion 5 in §13 is **rule-pool robustness**: the bench's
phenomenology must survive evaluation outside the rule strata where the
primitive library happens to be a good fit. Without an adversarial stratum,
the bench risks a silent failure mode where critical phenomenology shows up
*because* the truth distribution was secretly aligned with what the library
can express. Such results would not survive the Slow Bench transition and
would not generalize.

The adversarial stratum exists specifically to break this. The rules in it
must be:

1. **Structured** — generated by a compact recipe, not random bits, so the
   bench is testing whether the architecture can discover *some* structure
   even when its primitives are misaligned with the truth.
2. **Misaligned with every library primitive** — for each primitive, the
   rule's alignment score must be statistically indistinguishable from the
   alignment of a uniformly random rule. This is the hard requirement.

Hand-designing such rules turned out to be brittle (see §"What didn't
work" below), so the manifest uses a search procedure instead: generate
many structured candidates and *select* the ones that empirically test as
near-random against the entire library.

## Indexing and conventions

The 3×3 Moore neighborhood is indexed row-major:

```
position:   0 1 2
            3 4 5
            6 7 8
```

A configuration is an integer `n ∈ [0, 512)` whose bits encode the cell
states with position 0 as the most-significant bit:

```
b[k] = (n >> (8 - k)) & 1
```

A rule is a vector `r ∈ F_2^512` where `r[n]` is the next state of the
**center cell** (position 4) when the neighborhood is in configuration `n`.

The primitives implemented and verified:

| Primitive            | Description                                    | Rank |
|----------------------|------------------------------------------------|------|
| `C4_rotation`        | Invariance under 90° rotations                 | 372  |
| `Z2_horizontal`      | Invariance under horizontal reflection         | 224  |
| `D4_dihedral`        | Full dihedral symmetry of the square           | 410  |
| `color_inversion`    | $r(\bar n) = 1 + r(n)$ (life-like complement)  | 256  |
| `outer_totalistic`   | $r$ depends only on (center bit, live count)   | 494  |
| `affine_linear`      | $r$ is an affine linear function of the 9 bits | —    |

The first five ranks are computed from the actual constraint matrices
constructed in `build_manifest.py` and verified against the targets in
spec §4.2. **All five match exactly.** This is the foundation for trusting
every alignment score that follows.

The affine linear "primitive" is treated specially: it represents the entire
1024-element family of affine linear functions of the 9 input bits, and a
rule's alignment with this family is the **maximum** agreement fraction over
all 1024 functions. For Campaign 1, this is the explicit and load-bearing
restriction on the local-functional library from spec §4.3. An unrestricted
all-Boolean family of local functions is **not** intended here, because then
every hidden rule would trivially count as some local function and the
adversarial stratum would collapse. The relevant notion of vulnerability is
therefore whether a rule matches *some* affine linear function well.

## Random alignment baseline

To know what "library-misaligned" looks like quantitatively, the analysis
samples 200 uniformly random rules and measures their alignment with each
primitive. The result:

| Primitive          | Mean   | Std    | Max    | 99th percentile |
|--------------------|--------|--------|--------|-----------------|
| C4_rotation        | 0.498  | 0.020  | 0.550  | 0.546           |
| Z2_horizontal      | 0.495  | 0.032  | 0.580  | 0.563           |
| D4_dihedral        | 0.497  | 0.015  | 0.541  | 0.532           |
| color_inversion    | 0.501  | 0.032  | 0.605  | 0.583           |
| outer_totalistic   | 0.500  | 0.021  | 0.561  | 0.546           |
| best_affine_linear | 0.572  | 0.008  | 0.596  | 0.590           |

All five symmetry/OT primitives center on 0.50, as expected for homogeneous
constraints satisfied with probability 1/2 by random rules. The
best-affine-linear baseline sits at 0.57, slightly above 0.50, because we
are taking the maximum over 1024 functions and concentration inflates the
expected maximum; the 99th percentile is 0.59.

**Adversariality test:** an adversarial rule passes iff every primitive
alignment score is at most the corresponding 99th percentile + 0.02 (a
small tolerance for finite-sample noise in the baseline estimate).

Notes:

- Day & Night is the only life-like rule in the pool with complement

- Parity_9bit is included as the *most* aligned possible rule: it satisfies

Five distinct rules, all with exact 1.000 scores on the symmetry+OT
primitives that the library explicitly contains. Stratum verified.

## The adversarial stratum

The five adversarial rules are F_2 polynomials over the 9 input bits, with
mixed monomial degrees (3 or 4) and monomial counts (6 to 9). They were
selected from 4000 randomly generated structured candidates by the
following procedure (in `search_adversarial.py`):

1. Sample a polynomial: random constant ∈ {0,1} plus 4–9 random monomials of
   degree 1–4, with variables uniformly chosen.
2. Discard if the resulting rule's weight is outside [224, 288] (must be
   balanced; sparse rules pass symmetry tests trivially because most
   constraint pairs are (0,0)).
3. Discard if any symmetry-primitive alignment exceeds 0.60.
4. Discard if best affine linear alignment exceeds 0.62.
5. Of the surviving 289 candidates, sort by max alignment ascending and
   select the top five with diverse `(degree, monomial_count)` signatures
   so the stratum spans construction styles.

The five selected rules:

| Name         | Wt  | C4    | Z2h   | D4    | CInv  | OT    | Lin   |
|--------------|-----|-------|-------|-------|-------|-------|-------|
| ADV1_d4_m7   | 240 | 0.484 | 0.500 | 0.483 | 0.500 | 0.508 | 0.531 |
| ADV2_d3_m7   | 272 | 0.522 | 0.500 | 0.539 | 0.500 | 0.462 | 0.531 |
| ADV3_d4_m9   | 240 | 0.492 | 0.518 | 0.489 | 0.500 | 0.532 | 0.547 |
| ADV4_d3_m6   | 288 | 0.559 | 0.500 | 0.541 | 0.500 | 0.536 | 0.562 |
| ADV5_d3_m8   | 256 | 0.473 | 0.500 | 0.468 | 0.500 | 0.484 | 0.562 |

Every score is at or below the random baseline 99th percentile (with 0.02
tolerance). The adversariality verdict in the manifest records this
explicitly per primitive per rule. **All five rules pass.**

The full polynomial recipes are in the manifest under each rule's
`monomials` field. They are bit-for-bit reproducible from those recipes via
`polynomial_rule_from_recipe` in `assemble_manifest.py`.

A note on the CInv = 0.500 column: every adversarial rule scores **exactly**
0.500 on color inversion, not just near it. This is not a coincidence — it
follows from a structural property of polynomials of mixed-parity degree,
which produce exact 0.5 agreement with the constraint $r(\bar n) + r(n) = 1$.
This is a feature, not a bug: color inversion is the symmetry most
vulnerable to accidental hand-design alignment (the original ADV2 and ADV5
candidates both scored 1.000 on it because thresholds and majorities are
self-dual under bit complementation), and the search procedure finds rules
that decisively avoid that trap.

## The random stratum

Five rules sampled from `np.random.default_rng(seed=20260408)` in order.
The `draw_index` field (0..4) and the master seed are recorded in the
manifest, so any of the five rules can be regenerated bit-for-bit. The
five rules show alignment scores in the expected random range (0.46–0.53
on symmetry primitives, 0.56–0.58 on best linear), which is the third
sanity check on the analysis.

## What didn't work, and why this matters

The first attempt at adversarial rules used hand-designed nonlinear
functions: an asymmetric quadratic, a threshold on an L-shaped 5-cell
subset, an asymmetric cubic, a threshold on a 4-cell subset, and an
asymmetric depth-2 majority circuit. Of those five, only the first
(asymmetric quadratic) passed adversariality testing. The other four
all had visible structure under the library:

- The L-shaped 5-cell threshold scored **1.000 on color inversion**,
  because thresholding ≥3 of an odd-sized subset is exactly complementary
  to thresholding ≤2, which is the color-inverted condition.
- The cubic-three-triangles rule scored 0.68–0.72 across multiple symmetry
  primitives, well above the random band.
- The 4-subset threshold scored 0.79 on Z2 horizontal, despite the subset
  being asymmetric — the *function* (threshold) inherits structural
  correlations the *positions* don't have.
- The majority-chain rule scored **1.000 on color inversion** for the same
  reason as the L-shaped threshold: majority is self-dual.

The lesson is that "this rule looks asymmetric to me" is not the right test.
Several of the failure modes were invisible until measured. A library
primitive that scores 1.000 on a rule the designer thought was adversarial
would have silently destroyed criterion 5 in the first campaign, and the
results would have looked publishable while testing nothing.

The search-based replacement is robust because it tests the rules against
the library *before* selection rather than relying on intuition. If the
library is ever extended (e.g., adding $C_2$-only symmetry, or broadening
the Campaign-1 affine-linear local-functional family), the same search can
be re-run with the extended primitive set and a new manifest version
produced — the procedure does not need to be redesigned.

## Reproducibility checklist for VEX / Kepler

To verify the manifest end-to-end before locking it for the first campaign:

1. Run `python3 build_manifest.py`. Confirm all five primitive ranks
   match the spec targets exactly (372, 224, 410, 256, 494). Confirm that it
   prints sanity tables only and does **not** emit `campaign1_manifest.json`.
2. Run `python3 search_adversarial.py`. Confirm 289 candidates accepted
   from 4000 trials, the same five rules selected (same fingerprints), and
   the intermediate `adversarial_selection.json` written.
3. Run `python3 assemble_manifest.py`. Confirm "ALL ADVERSARIAL RULES PASS".
4. Inspect `campaign1_manifest.json`. The fields to spot-check:
    - `library_primitive_ranks` — every entry must show `match: true`.
    - `adversariality_verdict` — every entry must show
      `passes_adversariality_check: true`.
    - `campaign1_local_functional_library.kind` — must be `affine_linear`.
    - `canonical_emitter.script` — must be `assemble_manifest.py`.
    - For each rule in `rules`, verify the `fingerprint_sha256_16` matches
      a freshly computed fingerprint of the regenerated rule vector.

Fingerprint regeneration is the strongest check, because it confirms that
the recipe in the manifest reproduces the exact 512-bit vector that was
scored. If anyone modifies a rule's recipe or scoring method later, the
fingerprint will move and the change will be visible.

## What's deferred

Two things in §14 of the spec remain open and the manifest does not address
them:

1. **Expanding beyond 5/5/5.** The first campaign is committed to 15 rules.
   A v0.3 manifest might expand each stratum, particularly the adversarial
   one — generating, say, 50 adversarial rules and analyzing the
   distribution of bench performance across them rather than five point
   estimates. This would let cross-rule variance be reported alongside
   cross-policy variance and would make criterion 5 substantially stronger.
2. **Rollout-augmented conservation primitives.** The current `outer_totalistic`
   primitive is the closest approximation to a conservation law in single-step
   semantics. The spec defers true conservation to a later bench. When that
   bench exists, the adversarial search will need to be rerun with the
   extended primitive set, because rules that look adversarial against
   single-step primitives may turn out to be aligned against rollout-level
   ones (or vice versa).

Neither of these is a v0.2.2 blocker. The campaign-1.0 manifest is locked
when this document is approved.

## One-paragraph summary

The Fast Bench v0.2.2 hidden-rule pool is fixed as fifteen rules: five
life-like and parity rules that are exactly captured by the symmetry,
outer-totalistic, and Campaign-1 affine-linear local-functional primitives;
five F_2 polynomial rules selected by search to be statistically
indistinguishable from random under that library; and five seeded random
rules. Every primitive rank, every alignment score, every adversariality
verdict, and every random draw is reproducible from the scripts in this
directory. `assemble_manifest.py` is the sole canonical manifest emitter,
while `build_manifest.py` is analysis-only. The library primitive ranks
(372, 224, 410, 256, 494) match the spec exactly, which is the foundation
for trusting every downstream number. The manifest is ready to lock and hand
to VEX for the first throughput campaign.
